## 0. プロダクト概要

- **TabTreeNote**は、ローカルのテキストメモを「タブ×ツリー構造」で階層管理する個人用メモエディタ（Tauri + Rust、Windows 11優先）。`[DESIGN §1.1]`
- フリーソフト「CatMemoNote」を参考に、その思想（タブ＝フォルダ／メモ＝テキストファイル、3ペイン構成、DND操作、強力なテキスト処理、レジストリ非依存のポータブル思想）を引き継ぐ独自実装。`[DESIGN §1.2]`
- 想定ユーザー: プロジェクト作成者本人（個人用、プログラミング知識なし）。メモ・ToDo・断片情報等を階層的に貯める用途。`[DESIGN §1.4]`

## 2. v1由来のコア機能仕様

### 2.1 タブ管理（＝管理フォルダ）

- 上部タブバー、1タブ＝1管理フォルダ。新規作成／リネーム／削除（ごみ箱送り基本）。**タブ名の重複禁止**。
- ドラッグでの並べ替え、既存フォルダのドラッグ登録、クリック/ショートカット/マウスホイールでの切り替え。各タブは独立したツリーを持つ。
- **新規タブ作成・フォルダ登録はOS標準のフォルダ選択ダイアログを使う**（Web標準の`window.prompt()`等は使わない）。
- 検索ボタン左に「最前面に固定」ボタン（📌、セッション内のみ）。タブ右クリックに「タブの場所を開く」。

`[DESIGN §2.1]`

### 2.2 メモのツリー管理（左ペイン）

- フォルダ直下の`.md`のみをツリー走査・一覧表示（サブフォルダ内は対象外）。ロック中タブの内部表現は§4.1参照。
- 親子関係での階層化、開閉、接続線表示。リネーム・削除（ごみ箱送り）・上下/階層移動（**「複製」は右クリックメニューから撤去済み**、post-M7）。DNDでの並べ替え・階層変更・タブ間移動（Ctrl併用でコピー、§5.3の同期順序に従う）。複数選択（Ctrl/Shift）。メモへの色/種別ラベル。
- シンボリックリンク／ジャンクションは辿らない。
- **AutoReName（最初の非空行を自動でメモ名にする機能）は実装しない**（廃止・確定。経緯: [DECISIONS.md](DECISIONS.md)）。
- 追加位置の指定は無く、右クリック「メモを作成」（常に後ろに追加）／「子としてメモを作成」のいずれも、選択すると**即座に名前入力ダイアログを表示**する（issue.md時点の最新仕様。post-M7時点の「新しいメモ」自動命名+自動オープンから上書き）。
- **編集ロック**（`locked?: boolean`、本文編集のみ禁止、リネーム/削除は対象外、パスワード不要）。**§4.1のタブロックとは別物**。
- F2キーでリネーム（単一選択時）。↑/↓キーで前後メモへ移動（矢印キー移動中はエディタへフォーカスを奪われない。クリックオープン時は従来通りエディタへフォーカス）。開いているメモが変わった際、ツリー側の選択・スクロール位置も自動追従。
- 右クリックメニュー: 「アイコン」サブメニュー、「プロパティ」（ファイル情報+文字数カウント）。ツリーが空の時のみ中央に「メモを作成」ボタン表示。空白部分クリックでも選択。右クリックメニューは画面端では上方向に表示。
- **Deleteキー**: 行クリック直後はエディタへ自動フォーカスが移るため、素のDeleteキーはツリー削除に届かない。**§9.1で対応確定**（既存UXは維持し専用ショートカットを新設）。

`[DESIGN §2.2]`

### 2.3 テキスト編集（右ペイン）

- Undo/Redo（メモ切り替え時に履歴破棄、メモをまたいだUndoはしない）、切り取り/コピー/貼り付け、全選択、行単位操作。
- 折り返し切り替え（なし/文字数指定/ウィンドウ幅）、タブ幅、ソフトタブ、オートインデント、行番号表示、空白/改行の可視化トグル、カーソル行ハイライト。文字数/行数/カーソル位置をステータスバー表示。
- **文字コード**: 既定UTF-8。読み込みは「UTF-8（BOM検出）→不正バイト列ならShift_JIS再試行」の2段フォールバック。手動でのエンコーディング指定コマンドあり。
- **改行コード**: 読み込み時に検出した改行コードをそのまま維持して保存（既定）。ユーザー設定で統一も可能。エディタエンジンが内部でLF正規化する場合は、元の改行コード種別をメタ情報として保持し保存直前に復元する実装が必須（§4.2）。
- 右クリック: 「変換」（大文字/小文字/ひらがな/カタカナ/半角/全角/タブ⇄スペース）、「チェック」（☐/☑巡回挿入）、「Google で検索」、「プロパティ」。
- 本文中の☐/☑は**直接クリックでトグル**できる（右クリックメニューでの挿入とは別機能）。
- 「書式」サブメニューは無し（設定画面と重複するため）。ファイル名/エンコード帯での右クリック抑止。メモごとのスクロール位置記憶。
- **右クリックメニューの見た目統一**（エディタ/ツリー間）: **§9.1で対応確定**。

`[DESIGN §2.3]`

### 2.4 検索・置換

- 現在メモ内検索（インクリメンタル/次へ・前へ）、置換（単一/全置換/選択範囲/1つずつ）、正規表現対応、大文字小文字/単語単位オプション。検索履歴。
- **全文検索（全タブ横断）**: メモ名・本文を対象。実装方式は**メモリ内軽量インデックス**（起動時構築、外部DB・永続インデックスなし）。
  - **インデックス差分更新の2経路**: ①アプリ内変更（保存・リネーム・削除等）は保存完了時に直接インデックス更新／②外部からの変更はファイル監視経由のみ。
  - **ロック中タブの扱い**: ロック中・ロック解除セッション中を問わず、そのタブの名前・本文は常に全文検索インデックスから除外する（§4.1）。

`[DESIGN §2.4]`

### 2.5 外観・テーマ

- CSSベースのライト/ダークテーマを標準提供。配色・フォント・行間の基本カスタマイズ。
- UI文字サイズ設定（`uiFontScale`, 80〜150%、エディタ本文以外に適用）。

`[DESIGN §2.5]`

### 2.6 データ保存・永続化

- Markdown本文（`.md`）+タブ単位メタ情報（JSON）。保存タイミング: タブ切替時・別メモ読込時・最小化時・終了時・明示保存（Ctrl+S）・適度な自動保存（変更が無ければ書き込まない）。
- **アトミック書き込み＋直近1世代`.bak`**（対象範囲＝メモ本文・タブ単位メタJSON・アプリ設定JSON・タブロック関連ファイル。詳細§5.2）。
- OSごみ箱を使った安全な削除。ごみ箱送り失敗時はユーザー承諾のうえ直接削除（無確認削除はしない）。
- **ポータブル配置**: アプリ設定・タブ登録情報は`%APPDATA%`等ではなく**exe直下のフォルダ**（例: `config`/`data`）に保存する。exeをコピーするだけで設定・タブ登録が完全に独立したプロファイルになる（複数コピーの併用が可能）。
- 起動時に**前回開いていたメモを自動で開く**（`AppSettings.lastOpened`）。タブ/メモが削除済みなら何もしない。

`[DESIGN §2.6]`

### 2.7 ウィンドウ／操作

- 3ペイン（タブバー/ツリー/エディタ）+ステータスバー。スプリッターでツリー幅可変、左右配置切替、非表示。キーボードショートカット（ユーザー設定可能）。
- Windowsログイン時にトレイへ隠れた状態で自動起動する設定。
- **多重起動防止**: 2つ目の起動は既存ウィンドウをフォーカスするだけにする（同一設定ファイルへの同時書き込み事故を防止）。
- 登録済みタブ以外での右クリック抑止。タイトルバー右クリックの不要なネイティブ項目は`Menu.setApplicationMenu(null)`相当で解決。
- **タブバー空き領域ドラッグでのウィンドウ移動**: **§9.1で対応確定**。

`[DESIGN §2.7]`

### 2.8 リンク機能

- **自動リンク認識**: URL（`http://`/`https://`/`www.`/`ftp://`）、メールアドレス、ファイルパス（相対パスはタブ基準で絶対パス化してから開く）。
- **メモ間リンク（`memo:`記法）**: `memo:メモ名`（現在タブ内）／`memo:タブ名/メモ名`／`memo:タブ名/`。リンク先不明時は何もしない。
  - **ロック中タブへのリンク**: ロック中（セッション無し）のタブ内メモを指す`memo:`リンクは常に「未解決」として扱う（§4.1）。ロック解除セッション中は通常のリンクとして解決できる。
- 操作方法: 既定`singleClick`。外部起動前の確認ダイアログは既定OFF。OS標準API経由、シェル文字列連結は行わない。

`[DESIGN §2.8]`

### 2.9 パスワード保護（旧: 個別メモ暗号化）

> 個別メモ単位でのパスワード暗号化は提供しない。パスワード保護は**タブ単位のロック**に一本化。暗号方式（AES-256-GCM＋scrypt）はタブロックへそのまま踏襲。詳細仕様は**§4.1「タブロック」を参照**。

## 3. データモデル

### 3.1 基本方針

- メモ本体＝`.md`（UTF-8）。**メモの識別方法＝ファイル名**（UUID等の内部IDは導入しない、経緯: [DECISIONS.md](DECISIONS.md)）。表示名とファイル名は常に同一。
- **既知の制約**: リネーム＝ファイルリネームのため`memo:`リンクが切れる。
- **ファイル名サニタイズ**: Windows禁止文字・制御文字・予約名を入力/リネーム時点で検出しブロック。リアルタイムバリデーション表示＋置換候補提示（例: `/`→`-`/`_`）。
- タブ＝フォルダ、直下`.md`のみ対象、同一メモ名空間で重複禁止。

`[DESIGN §3.1]`

### 3.2 メタ情報

- タブ単位メタファイル（`.tabtreenote.json`、フォルダ内隠しメタ）にツリー構造・順序・開閉・ラベル・エディタ設定を保存。ロック中はこの`tree`が`lock`ブロブに置き換わる（§4.1）。
- **堅牢性の中核原則**: メタ情報が失われてもメモ本体（`.md`）は決して失わない（メタ喪失時はフラット再生成で復旧、§5.9）。
- メタJSON・アプリ設定JSONもアトミック書き込み＋`.bak`の対象（§5.2）。`schemaVersion`+`appVersion`を記録。
- 実ファイルとメタJSONの同期順序: §5.3参照。

`[DESIGN §3.2]`

### 3.3 外部変更への追従

- ファイル監視でフォルダ内容変更を自動検知・反映。自己発火除外・競合判定・Windowsロック対策は§5.4/§5.5/§5.7参照。

`[DESIGN §3.3]`

## 4. TabTreeNoteMD独自機能仕様（ロック機構の再設計・Markdown全面移行）

### 4.1 ロック機構: タブロック（新設）

| 旧機能 | 状態 |
|---|---|
| ノードロック（サブツリー単位、旧DESIGNv3 §1） | **廃止** |
| M6個別メモ暗号化（`.txtenc`、旧DESIGN §2.9） | **廃止** |
| 編集ロック（`locked?: boolean`、パスワード不要） | **維持**（§2.2） |
| タブロック | **新設** |

**仕様**:
- ロック対象は**タブ（管理フォルダ）単位**。パスワードで解除しない限り**中身（ツリー・メモ）を一切見ることができず**、**タブ名自体もタブバー上で隠す**（🔒表示）。
- **ロック中のタブは削除できない**（先にロック解除が必要）。
- パスワード入力UIはヒント表示に対応（設定時に任意のヒント登録、解除時に表示）。
- 暗号方式は**AES-256-GCM＋scrypt**。

**内部実装方式**（常駐セッション＋難読化ファイル名＋暗号化ブロブ方式。タブの中に「ロックされていない兄弟部分」が無いため、入れ子ロック・恒久解除操作は無い。ただしタブ間のメモ移動は別途8参照）:

1. ロック時、タブ直下の全`.md`を128bitランダム16進数トークン（`crypto.randomBytes(16).toString('hex')`、衝突時再生成）へリネームし、各ファイルの内容自体も個別にAES-256-GCMで暗号化する。
2. 元のツリー構造・実タブ名・「実メモ名↔難読化トークン」対応表を1つの暗号化ブロブにまとめ、**そのタブ自身の`.tabtreenote.json`内**（`tree`フィールドの代わりに`lock`フィールド）に保存する。フォルダごとコピーしてもロック状態ごと持ち運べる（§6可搬性）。
3. `AppSettings.tabs[i].name`は実名を残さずプレースホルダに置換（実名はブロブ内にのみ存在）。`locked: boolean`はタブバー描画用の軽量キャッシュ（真実源はタブ自身の`.tabtreenote.json`側の`lock`フィールド）。
4. **ロック解除（セッション開始）**: パスワード入力→ブロブ復号→実タブ名・実構造・名前対応表をメモリ上の「ロックセッション」として保持。編集内容は都度、対応表・構造ブロブを再暗号化（新IV）してアトミック保存し、各メモ本文も個別に再暗号化して書き戻す。
5. **セッション寿命**: タブから離れる（別タブ選択）と即座に破棄（経緯: [DECISIONS.md](DECISIONS.md)）。再度開く際は毎回パスワード再入力が必要（不便であれば見直す）。
6. **全文検索**: ロック中・セッション中を問わず常にそのタブの名前・本文をインデックスから除外（§2.4）。
7. **削除制限**: ロック中（セッション無し）は`tab:remove`を拒否（`TAB_LOCKED`）。セッション中は通常のタブ削除と同様に扱える。ロックを完全に取りやめたい場合は、単に以後「タブのロック」を再設定しないだけでよい。
8. **タブ間のメモ移動（DND）**: このアプリのタブ間DNDは「今アクティブなタブのツリーからドラッグし、タブバー上の別タブへドロップする」方式で、ドラッグ元のタブを離れずに完結する（ルール5の「タブを離れたら即セッション破棄」とは衝突しない）。
   - **他タブ→ロック中（セッション無し）タブへドロップ**: **ドロップした瞬間にその場でパスワード入力ダイアログを表示**し、成功したらそのままセッションを開始してメモを取り込む（ドラッグ元タブから離れる必要はない）。「先にタブを開いてロック解除してから」という手順は、ロック解除後にドラッグ元タブへ戻る時点でルール5により再ロックされてしまうため成立しない。
   - **ロック解除セッション中タブ→他（通常の）タブへドロップ**: **許可**。移動した瞬間にそのメモは復号され、移動先タブでは通常の平文`.md`ファイルになる（旧ノードロックの「一方通行の金庫」方式は採用しない。タブ丸ごとのロックのため、同一ツリー内で保護部分と非保護部分が隣接する事故のリスクが無いため）。

`[旧: docs/v3/DESIGNv3.md §1／DESIGN.md §2.9 は不採用。暗号方式・技術パターンのみ転用]`

### 4.2 Markdown編集（CommonMarkフル対応）

- **全メモがMarkdown（`.md`）に統一**（§1 Q2）。プレーンテキストの選択肢は廃止。
- **編集体験＝ライブビューがデフォルト**。ソース（生Markdown）表示への切り替えも可能。
- **Markdown対応範囲＝CommonMark相当のフル対応**: 見出し・箇条書き・引用・コードブロック・表・強調（太字/斜体）・水平線・リンク等。
- **ツールバー＝フル機能かつフロート可能**: 見出し/箇条書き/引用/コードブロック/表/強調/リンク/画像挿入等をツールバーから操作可能。ウィンドウ内で自由に位置移動できるフローティングパネル。
- **画像貼り付け・リサイズ**:
  - クリップボードからの貼り付けに対応。実体は**メモが属するタブのフォルダ直下に保存**（サブフォルダは作らない）。
  - **ファイル名生成規則**: `img_<crypto.randomBytes(8).toString('hex')>.<拡張子>`（例: `img_a3f9c1e2b7d4e6f1.png`）。衝突時は再生成。拡張子は実形式から決定、クリップボード由来の生ビットマップは既定`.png`。
  - **リサイズ結果は`<img src="相対パス" width=".." height="..">`のHTML形式で保存**（標準記法`![alt](url)`にはwidth/height情報を置けないため。リサイズ未実施の画像は`![alt](url)`のままでよい）。
  - **孤立ファイルの自動掃除は行わない**（確定）。メモ削除・画像参照除去後も画像ファイルは残る。手動整理のみ（複数メモからの参照有無を誤判定して削除するデータ消失リスクを避けるため）。
- **装飾表現の記法（ハイブリッド、確定）**: 太字/斜体は標準Markdown記法（`**太字**`/`*斜体*`）を使う。文字色・文字サイズは標準Markdownに記法が無いため`<span style="color:...;font-size:...">`の許可リスト方式を使う。
- **安全性**: 許可するタグ・属性は許可リスト方式（`<img>`の`src`/`width`/`height`、相対パス参照のみ。`<span>`は`style`の`color`/`font-size`のみ）。**許可リスト外のタグ・属性・CSSプロパティ（`<script>`・`on*`イベント属性・`javascript:`スキーム等を含む）はプレビュー描画時に必ず除去する**（`position`等の任意CSSプロパティは許可しない）。
- **Markdownリンク記法との共存（確定）**: 標準のMarkdownリンク記法`[text](url)`を有効化する。`memo:`はURLスキームの一種として扱い、`[見出しへ](memo:タブ名/メモ名)`のようにラベル付きのメモ間リンクを書けるようにする（§2.8の`memo:`直書き記法と併存）。
- **全文検索**: 装飾・構造用のMarkdown記法/HTMLタグを除去（プレーンテキスト化）してからインデックス対象にする。
- **エディタエンジン**: 未確定。CodeMirror 6の装飾拡張、またはMilkdown/TipTap等のMarkdownネイティブなWYSIWYGライブラリを候補として詳細設計フェーズで確定する。

`[旧: docs/v3/DESIGNv3.md §2 は不採用（全面置換）]`

## 5. 横断的原則

### 5.1 `Result<T>` 型規約とエラーコード

IPCは`Result<T>`（discriminated union）で統一。例外は境界で捕捉しエラーコード化。型定義は§3.4参照。

### 5.2 アトミック書き込みパターン

全ての永続化保存は「① tempファイルへ書込 → ② fsync → ③ 旧targetを`.bak`へrename（世代スワップ） → ④ tempをtargetへrename」の順。

- 対象範囲: メモ本文（`.md`）／タブ単位メタJSON（ロック中はロックブロブを含む）／アプリ設定JSON／タブロック中の難読化ファイル。直近1世代のみ`.bak`。

### 5.3 実ファイルとメタJSONの同期順序

リネーム・移動・コピー・複製など両方に影響する操作は: ①ストア更新（メモリ上）→②実ファイル操作+自己書き込み予約テーブル登録→③実ファイル操作成功直後にメタJSONをアトミック保存。極稀にこの隙でクラッシュした場合はメタ復旧カスケード（§5.9）が安全網。

### 5.4 自己書き込み予約テーブル

アプリ自身のFS操作を監視イベントの誤検知から守る仕組み。一時ファイルは固定プレフィックスで監視除外。アプリ発の操作（アトミック書き込み・`.bak`生成・リネーム・ごみ箱送り/直接削除・DND移動/コピー/複製・タブロックの難読化リネーム）は実行前に予約テーブルへ登録し、対応監視イベントを自己発火として破棄。予約登録はfs層に一元化。レコード寿命＝マッチしたら即時クリア＋TTLフォールバック（既定2〜3秒）。

### 5.5 競合判定の2系統

- 保存API＝**ハッシュ比較のみ**（実行時点のディスク実体ハッシュとレンダラ保持の`expectedHash`を一発判定）。
- ファイル監視側（自己発火判定・外部変更検知）＝**mtime+サイズ+ハッシュの複合判定**。

### 5.6 hashフィールドの対象

全て「ディスク上の実ファイル全体（バイト列）のハッシュ」。

### 5.7 Windowsロックエラーのリトライ方針

書込・rename・削除の各操作に短いリトライ（例3〜5回、50〜200msバックオフ）。全滅時のみ`IO_LOCKED`をユーザー表示。

### 5.8 エラーハンドリング表

| 事象 | 方針 |
|------|------|
| Windowsロック（EBUSY/EPERM） | 短いリトライ後、全滅時のみ`IO_LOCKED`表示 |
| ごみ箱送り失敗 | `TRASH_FAILED`→確認ダイアログ→**承諾時のみ**直接削除 |
| メタJSON破損 | 復旧カスケード（`.bak`→フラット再生成→通知）。メモ本体は決して失わない |
| アプリ設定JSON破損 | 同様の復旧。全滅時は既定設定で再生成し通知 |
| 復号失敗（タブロック） | `DECRYPT_FAILED`「パスワードが違います」。中身は一切返さない |
| 外部編集競合 | mtime+サイズ+ハッシュで判定。編集中なら`evt:conflict`、解決ダイアログ中は自動保存/入力ロック |
| 名前重複/禁止文字 | ファイル操作前に検出しブロック（`NAME_DUPLICATE`/`NAME_INVALID`）。実ファイルは触らない |
| ロック中タブへの操作 | `TAB_LOCKED`で拒否（§4.1） |
| 長パス | `LONG_PATH`警告。正式対応外 |
| 予期せぬ例外 | 境界で必ずcatchし`{ok:false, code:'UNKNOWN'}`化。レンダラへは`code`/`message`/`path?`のみ、詳細はメインプロセス内部ログのみに記録 |

### 5.9 メタ破損復旧カスケード

1. 直近`.bak`があれば復旧を試行。
2. 無い/失敗ならフォルダ直下実ファイルから**フラット構造でメタ再生成**（階層・ラベル等は失うがメモ本体は保持）。
3. ユーザーへ「メタ情報を再構築しました」と通知。

### 5.10 セキュリティ不変条件と内部診断ログ方針

- 鍵/パスワードは境界の内側に閉じる。復号平文はディスクへ書き出さない・インデックスに入れない・内部ログにも出さない。
- 外部起動はOS標準APIのみ、シェル文字列連結はしない。
- `Result`のエラーは`code`/`message`/`path?`のみ外部へ。詳細（OSエラーコード・例外・スタック）は内部ログにのみ記録（鍵・パスワード・復号平文は内部ログにも出さない）。

### 5.11 名前サニタイズ／バリデーション

Windows禁止文字・予約名・前後空白/末尾ピリオドを検出。リアルタイムバリデーション表示、`/`等の置換候補提示。タブ名は重複禁止、メモ名は同一タブ内の`.md`単一空間で重複禁止。長パス（260文字超）は`LONG_PATH`警告。

`[00-core-principles.md がベース]`

## 6. 非機能要件

- **動作環境**: Windows 11主対象。
- **パフォーマンス**: 数百〜数千メモ規模でも軽快なツリー描画・検索。全文検索はメモリ内軽量インデックス。
- **信頼性**: データ本体は常に独立ファイルとして保持。メタ破損でも本文は失わない。アトミック書き込み＋直近1世代`.bak`。
- **可搬性/バックアップ**: フォルダごとコピーでバックアップ可能（タブロック中でも成立、§4.1）。
- **既知の制限**: 260文字超のロングパスは正式対応外。
- **セキュリティ**: AES-256-GCM+scrypt（タブロック、§4.1）。鍵はセッション内メモリのみ。外部連携なし（ローカル完結）。

## 7. 引き継ぐべき実装ルール（M7完成後の修正から）

- フォルダ不在時は例外を投げず空配列を返す（外部からタブ登録フォルダを削除された場合の耐性）。
