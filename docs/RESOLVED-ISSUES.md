# Resolved Issues (RESOLVED-ISSUES.md)

> Log of closed GitHub issues (repo `hachi921082-source/TabTreeNoteMD`). Per [CLAUDE.md](../CLAUDE.md)'s
> "GitHub Issue Workflow": once an issue's fix is merged, the issue itself is **closed** (not
> deleted — GitHub keeps the full discussion history), and a short entry is added here so the
> resolution history is also browsable directly in the repo without going through GitHub.

> **Format per entry**: `- #<number> <title> — <one-line summary of the fix> (PR #<pr-number>)`

---

## Closed

- #20 Bare file-path auto-link click-to-open has no `..`-traversal guard (security-relevant) — `resolve_file_path` now rejects relative targets with a `..` segment or a rooted-but-not-absolute path (e.g. `\Windows\System32\cmd.exe`), mirroring `markdownSanitize.ts`'s `isSafeRelativeImageSrc` (PR #32)
- #11 `markdown-editing/PLAN.md` described the toolbar's "Update" slot as calling a removed stub — corrected to describe the real `tocGenerator.ts` wiring (PR #33)
- #14 `Cargo.toml`'s `tauri-plugin-autostart` comment described the abandoned Startup-folder approach — corrected to describe the shipped Registry `HKCU\...\Run` key (PR #34)
- #16 Toolbar image-insert file input leaked on dialog cancel — `insertImageViaFilePicker` now cleans up on `cancel`/`focus` fallback, not just `change` (PR #35)
- #19 Bare `memo:` with nothing after the colon matched as a link — `BARE_MEMO_RE` now requires at least one non-whitespace target char (PR #36)
- #17 Tab Lock session mutations weren't rolled back if the final lock-blob save failed — all 7 session mutators now route through a build-then-commit `commit_session_mutation` helper that only applies the in-memory `tree`/`file_map` change after `save_lock_blob` succeeds (PR #37)
- #18 `cleanup_session_move_source` swallowed source file-delete failures instead of aborting, risking orphaned encrypted files after a cross-tab move — reordered to delete the physical file first and abort (leaving `tree`/`file_map` untouched) on failure, matching `session_delete_memo`'s pattern (PR #38)
- #23 Clicking a memo no longer auto-focused the editor (spec-mandated) — added a one-shot `focusEditorToken` signal in `useTree.ts`, bumped by click-open/`focusOnMemo` but not arrow-key nav, consumed by `EditorPane.tsx`'s view-creation effect to call `view.focus()`; user-tested and confirmed (PR #39)
- #29 Cursor landed before (not after) the inserted `"> "`/`"- "` prefix after the Quote/List toolbar button — `toggleLinePrefix` now maps the pre-edit selection through its `ChangeSet` with `assoc=1` instead of relying on CodeMirror's default left-sticking mapping (PR #40)
- #25 Markdown toolbar's rearrange mode didn't work — its slot-reorder drag used the HTML5 DnD API, which conflicts with Tauri's native drag-drop on Windows; switched to the same pointer-event pattern `TabBar.tsx` uses for tab reordering (PR #41)
- #5 Settings dialog content (20+-row Shortcuts section) overflowed the window with no scrollbar — `.ttn-dialog-body`'s missing flex/`min-height:0` broke the intended flex-scroll chain; fixed with a scoped `.ttn-dialog.ttn-settings-dialog .ttn-dialog-body` rule rather than the shared `Dialog.css`, to avoid a margin-collapse regression in `ConflictDialog` (PR #42)
- #31 The Markdown toolbar's live/source view toggle only affected the current session, never surviving a memo reopen or app restart — `onToggleLiveView` now persists into the memo's `MemoEditorSettings.viewMode` override, following `persistScrollPosition`'s existing per-memo pattern; `detailed-spec.md` §5.10 updated to match (PR #43)
- #28 Reopening a memo restored scroll position but not cursor position — added paired `cursorAnchor`/`cursorHead` fields alongside `scrollPosition`, threaded through both Rust load paths and restored via `EditorState.create`; also fixed a pre-existing memo-switch race where the outgoing memo's final position was written into the newly-opened memo's override instead (PR #44)
- #24 The floating Markdown toolbar could be dragged (or left stranded by a window shrink) outside the editor pane, causing a duplicate scrollbar and pushing the title bar off-screen — added `clampToolbarPosition`, wired into mount/read, drag, and a new window-resize listener; resize-triggered persistence is debounced to avoid a disk write per animation frame (PR #45)
- #26 Added a minimize button to the Markdown toolbar — collapses to header-only and snaps to the pane's bottom-right corner via issue #24's `clampToolbarPosition`, restoring to the pre-minimize position; new `toolbarMinimized` field follows `treeCollapsed`'s pattern; fixed a settings-load render race that corrupted the saved position on every restart while minimized (PR #46)
- #21 The `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` env var never actually opened WebView2's CDP remote-debugging port (wry always passes its own non-null arg string, which WebView2 prioritizes over the env var) — switched to `WebviewWindowBuilder::additional_browser_args`, requiring the main window to be created programmatically in `.setup()` instead of declaratively; live-verified via an actual CDP screenshot of the rendered app (PR #47)
- #22 `markdown-editing/PLAN.md` §9 scenario 4 (selection survives rapid live/source toggle) was left unconfirmed pending issue #21's CDP fix — not a code fix, re-verified live via real CDP-driven interaction: a selection spanning a `**bold**` decoration boundary survived 6 rapid toggles unchanged, document content byte-identical throughout (PR #48)
- #30 A single-line text selection showed no visible highlight (multi-line selections were fine) — CodeMirror's negative-z-index selection layer was fully occluded by `.cm-activeLine`'s opaque background on the cursor's own line; switched to a translucent `--ttn-bg-active-line`, verified visually via CDP screenshots in both themes/view modes (PR #49)
- #4 Cross-tab search had no way to scope a search to just the active tab (old app had this) — added the old radio-button selector back (全タブ/現在のタブ), with 現在のタブ as the new default per user decision; `scopeTabId` resolves fresh per search so a mid-dialog tab switch is followed correctly (PR #50)
- #9 Properties dialog (both the editor and tree-node context-menu variants) was missing file name/path and only showed a single character total — `MemoProperties` gained `fileName`/`filePath`/`charCountExcludingWhitespace`/`lineCount`, all char/line counts now computed from the LF-normalized body in both the plain and tab-locked/session paths; the locked path shows the logical path, never the obfuscated on-disk token filename (PR #51)
- #10 Properties dialog formatting/reveal-button gaps versus the old app — grouped fields into "ファイル情報"/"文字数カウント" sections; `created`/`modified` switched from a backend-pre-formatted UTC string to raw epoch-ms, formatted client-side with weekday + local time + relative "n日前" (also fixing a latent 9h-off-from-local-time bug); new `memo_open_location` command backs a "ファイルの場所を開く(O)" button, revealing the specific file for a plain tab or just the tab's folder for a locked/session tab (PR #52)
- #6 Settings "一般" tab crammed Appearance/Links/Startup/Shortcuts (20+ rows) into one screen — split Shortcuts out into its own new "ショートカット" tab (一般/ショートカット/エディタ order), a pure JSX relocation with no state/handler changes (PR #53)
- #15 `sanitizeMarkdownHtml()` (DOMPurify-based) was dead code, never called anywhere — real enforcement is `filterStyleDeclarations()`/`isSafeRelativeImageSrc()` called directly by `markdownSpanParser.ts` (no HTML string is ever built for a sanitizer to run over); removed the dead code + `dompurify` dependency, corrected 3 PLAN.md docs that still described the DOMPurify-based mechanism (PR #54)
- #3 Cross-tab search dialog wording differed from the old app — title 検索→全文検索, checkbox label 大文字/小文字を区別→大文字小文字区別, placeholder simplified to a static "検索語を入力..." (scope already shown by the visible 全タブ/現在のタブ radio buttons) (PR #55)
- #8 Context menu accordion submenu could render off-screen (horizontal and vertical) when expanded near a screen edge — original ask was accordion→flyout matching the old app, but after a cost/robustness discussion the decision was to keep the accordion and instead harden it: real DOM measurement (useLayoutEffect) replaces the old rough height estimate, adds a horizontal clamp (previously nonexistent), and a hard maxHeight cap + overflow-y:auto scroll fallback guarantees no overflow regardless of measurement accuracy; also fixed a box-sizing precision gap found in review (PR #56)
